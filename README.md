# 🚀 To-Do Rewards — телеграм-бот + мини-приложение

Список задач с напоминаниями и игровой системой наград: опыт, уровни, монеты,
серии дней, достижения и магазин, где монеты меняются на темы оформления
и «честно заслуженные» радости.

Всё работает в одном процессе: `aiogram` (бот) + `FastAPI` (API и мини-приложение) + SQLite.

---

## Что умеет

**Бот**
- Любое сообщение превращается в задачу: `завтра в 18:00 позвонить маме`, `через 40 минут вынести мусор`, `купить кофе !!`
- Понимает: `сегодня / завтра / послезавтра`, дни недели, `25.12`, `18:30`, `через N минут/часов/дней`, `каждый день / по будням / каждую неделю`
- Сам подбирает эмодзи и приоритет по смыслу
- ⏰ Присылает напоминания с кнопками «Выполнено» и «Отложить на 10 мин / час / завтра»
- Команды: `/list`, `/today`, `/add`, `/stats`, `/shop`, `/clear`, `/help`

**Мини-приложение (Web App)**
- Живой градиентный фон, стеклянные карточки, плавные пружинные анимации
- Кольцо уровня, XP-полоса, счётчики монет / серии / выполненного
- Вкладки: Сегодня · Все · Награды · Магазин
- Конфетти, летящие «+XP», хаптик-отклик и оверлей нового уровня
- Нижний лист создания задачи: эмодзи, приоритет, быстрые сроки, повтор
- 6 тем оформления, которые покупаются за монеты

**Награды**
| Что | Как считается |
|---|---|
| Опыт | 10 XP + приоритет (0/5/15) + 5 XP за выполнение в срок, всё × множитель серии |
| Монеты | половина полученного опыта |
| Уровень | 100, 300, 600, 1000… XP (10 званий от «Новичка» до «Бога тайм-менеджмента») |
| Серия | +10 % к награде за каждый день подряд, максимум ×2 |
| Достижения | 14 штук, каждое даёт монеты |

## Запуск

Части две и они независимы: **бот** работает от одного токена, **мини-приложение**
дополнительно требует публичный HTTPS-адрес.

### Шаг 1. Токен

[@BotFather](https://t.me/BotFather) → `/newbot` → имя → username (оканчивается на `bot`).
Полученный токен вписать в `.env`:

```bash
cp .env.example .env   # если файла ещё нет
open -e .env           # заменить строку BOT_TOKEN=
```

### Шаг 2. Запуск

**С мини-приложением** (поднимает туннель, сам подставляет адрес в `.env`):

```bash
./start.sh
```

Скрипт поднимает туннель, кладёт адрес вида `https://xxxxx.lhr.life` в файл
`.webapp_url` и запускает сервер с ботом. Кнопка «🚀 Открыть To-Do» заработает
сразу после `/start`.

Бесплатные туннели периодически рвут соединение — скрипт следит за этим и
поднимает туннель заново сам, не трогая бота (polling не прерывается). Бот
читает `.webapp_url` при каждой отрисовке кнопки, поэтому свежий адрес
подхватывается без перезапуска: достаточно ещё раз нажать `/start`.

Провайдеры перебираются по очереди — `localhost.run` (по SSH, ничего ставить не
нужно), затем `serveo.net`, затем `cloudflared`. Первых двух почти всегда
достаточно. Третий — запасной, его бинарник в репозиторий не входит и ставится
отдельно:

```bash
./get-cloudflared.sh
```

`trycloudflare.com` у многих провайдеров заблокирован, поэтому он последний в очереди.

Адрес временный и меняется при каждом перезапуске. Постоянный даёт свой домен
(см. «Заметки по эксплуатации»).

Отдельно вставлять адрес в @BotFather (`/mybots` → бот → **Bot Settings → Menu
Button**) нужно только чтобы кнопка висела ещё и в меню чата — на работу
мини-приложения это не влияет.

**Только бот, без интерфейса** (туннель не нужен):

```bash
./run.sh
```

Терминал не закрывать — пока он открыт, бот и напоминания живут.

### Шаг 3. Проверка

Найти бота по username → `/start` → написать ему `через 3 минуты проверить напоминание`.
Через три минуты придёт сообщение с кнопками. Нажать ✅ — начислятся опыт, монеты
и достижение.

`cloudflared` лежит в `tools/` внутри проекта и в системный PATH не прописан —
поэтому `cloudflared ...` из любой папки не сработает, вызывай через `./start.sh`.

## Развёртывание на Vercel

Проект умеет работать в двух режимах. Локально — постоянный процесс с polling и
фоновым планировщиком. На Vercel постоянных процессов нет, поэтому там:

| Задача | Локально | На Vercel |
|---|---|---|
| Приём сообщений | polling | вебхук `POST /webhook/<секрет>` |
| Напоминания | цикл раз в 20 сек | `GET /api/cron/reminders?key=…` по расписанию |
| База | тот же Postgres | тот же Postgres |

Код выбирает режим сам по переменной `VERCEL`, которую платформа выставляет.

### 1. База

Панель Vercel → **Storage** → **Create Database** → **Neon** → привязать к проекту.
Переменные `DATABASE_URL` и `POSTGRES_URL` подставятся автоматически. Таблицы
создадутся при первом запросе.

### 2. Переменные окружения

Settings → **Environment Variables** → добавить `BOT_TOKEN`. Больше ничего не нужно:
секреты вебхука и cron выводятся из токена детерминированно, поэтому совпадают
локально и на сервере.

### 3. Включить вебхук

Один раз открыть в браузере адрес, который печатает команда:

```bash
./.venv/bin/python -c "from bot.config import CRON_SECRET, webapp_url; print('/api/setup?key=' + CRON_SECRET)"
```

Эндпоинт переключит бота на вебхук по текущему домену и вернёт JSON с адресами.
Состояние в любой момент видно на `/api/status`.

### 4. Напоминания по расписанию

`vercel.json` содержит крон, но на тарифе Hobby он запускается **раз в сутки** —
для напоминаний этого мало. Бесплатное решение: [cron-job.org](https://cron-job.org)
или подобный сервис, дёргающий раз в минуту

```
https://<домен>/api/cron/reminders?key=<CRON_SECRET>
```

Точный адрес с ключом печатает команда из шага 3 (поле `cron` в ответе `/api/setup`).

> ⚠️ Telegram отдаёт апдейты **либо** в вебхук, **либо** в polling. Локальный
> `./start.sh` снимает вебхук при запуске — после него бот на Vercel замолчит,
> пока снова не открыть `/api/setup`. Держи включённым что-то одно.

## Разработка без Telegram

При `DEV_MODE=1` приложение открывается прямо в браузере на `http://localhost:8080`
под тестовым пользователем — удобно для правки интерфейса. Запускать при этом
достаточно `./run.sh`.

> ⚠️ Как только адрес становится публичным (туннель или домен) — ставь `DEV_MODE=0`.
> При `DEV_MODE=1` подпись `initData` не проверяется, и любой, кто знает ссылку,
> попадёт в приложение под тестовым пользователем.

## API

Все запросы требуют заголовок `X-Telegram-Init-Data` с `initData` из Telegram Web App.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/state` | пользователь, задачи, достижения, магазин |
| `POST` | `/api/tasks` | создать задачу (`smart: true` — разобрать время из текста) |
| `PATCH` | `/api/tasks/{id}` | изменить; `done: true` начисляет награды |
| `DELETE` | `/api/tasks/{id}` | удалить |
| `POST` | `/api/tasks/clear-done` | убрать выполненные |
| `POST` | `/api/shop/buy` | купить товар / включить тему |
| `POST` | `/api/settings` | часовой пояс, тема |

Интерактивная документация: `http://localhost:8080/api/docs`

## Заметки по эксплуатации

- Напоминания проверяются каждые 20 секунд (`REMINDER_TICK` в `bot/config.py`).
- Часовой пояс подтягивается из браузера при первом открытии приложения;
  по умолчанию — `DEFAULT_TZ_OFFSET` из `.env`.
- Повторяющаяся задача при выполнении сразу создаёт следующий экземпляр.
- Для постоянного хостинга подойдёт любой VPS: `systemd`-юнит на `main.py`
  плюс `nginx` с сертификатом на домен из `WEBAPP_URL`. Тогда адрес перестанет
  меняться и туннель будет не нужен.
- Если ни один туннель не поднимается — это сеть, а не проект: `./run.sh`
  запустит бота без мини-приложения, всё остальное продолжит работать.
- `.webapp_url` — служебный файл с текущим адресом туннеля. Его пишет `start.sh`,
  а `run.sh` удаляет, чтобы бот не предлагал кнопку на мёртвый адрес.
